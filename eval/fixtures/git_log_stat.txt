    feat(llm): cache the growing conversation across tool round-trips via Faraday middleware (#311)
    
    ruby_llm 1.16 runs the whole model<->tool loop inside one ask(), so the
    intermediate tool round-trips never re-enter rubino's per-turn code. The
    only seam that sees every actual outgoing request — including those
    intermediate round-trips — is a Faraday request middleware on the
    Anthropic connection.
    
    CacheBreakpointMiddleware stamps cache_control: {type: ephemeral} on the
    last content block of the last message of EVERY /messages request, so the
    moving conversation tail is cached and read back turn after turn
    (Anthropic longest-cached-prefix). On a tool turn the tail block is a
    tool_use or tool_result; it is stamped unconditionally as a wire-valid
    sibling key, never restructured. A bare-string tail is skipped.
    
    The 4-breakpoint cap is honored: static tools+system breakpoints are
    never evicted; the oldest message-level breakpoint is evicted first. A
    long turn (>20 content blocks) earns an optional second leapfrog
    breakpoint ~15 blocks behind the tail. Any parse/shape surprise leaves
    the body byte-identical (defensive rescue).
    
    Wired only on the anthropic-family path and only when prompts.prompt_cache
    is on (same gate as the existing system-prefix and last-tool
    breakpoints); openai/ollama connections never carry it. The middleware is
    inserted into the live Faraday builder via the public
    Provider#connection seam — no monkey-patch — and is idempotent across
    reused connections.
    
    Live wire check against MiniMax /anthropic through a logging proxy: a
    tool-heavy turn issued 4 requests; all 4, including the 3 intermediate
    tool round-trips whose tail is a tool_result, carried the tail breakpoint
    (3 total: tools+system+tail), and cache_read climbed across round-trips —
    exactly the round-trips a per-ask() tail stamp would miss.

    feat(compression): reversible Ruby code skeleton for whole-file reads (off by default)
    
    Phase 1 of deterministic, reversible compression of tool-read results to cut
    tokens when the agent reads large Ruby files for exploration. OFF by default —
    lands inert (zero behaviour change) so it can be measured before flipping on.
    
    New module Rubino::Compression (Zeitwerk-autoloaded):
    - CompressionResult: immutable value object (text, byte/token deltas, ratio,
      strategy, applied?).
    - Compressor: entry point that routes by content type (Phase 1: :code Ruby →
      skeleton; everything else a no-op) and enforces conservative guards
      (whole-file only, >= min_lines, >= 25% saving, parse must succeed).
    - RubyCodeSkeleton: Prism-based AST walk. Keeps requires, comments, constants,
      attr_*, module/class structure, signatures and small method bodies verbatim;
      elides each large method body behind a single pointer line that IS a targeted
      read of the exact original lines:
        # … 14 lines elided — read path offset=120 limit=14
    
    Drill-in invariant (the safety story): a whole-file read (no offset/limit) is
    exploration and may be skeletonised; a targeted offset/limit read is NEVER
    compressed and returns verbatim bytes. The pointer's offset/limit are exact
    1-based line numbers into the original file, so following a pointer returns the
    elided body byte-for-byte — the edit tool's exact-string match still works.
    
    Wiring (ReadTool, gated on tool_output_compression.enabled, default false):
    - whole-file Ruby read → skeleton + dim "⚡ compressed …" notice via the tool
      activity channel + per-session saved-token total on ReadTracker.
    - targeted read into a previously-elided range → logs compression.drill_in
      (the "did the skeleton hide what was needed" signal).
    - a skeleton apply logs compression.applied with ratio/bytes/tokens.
    - any compression error falls back to the verbatim read (logged).
    
    Config: tool_output_compression.{enabled:false, code:{strategy, min_lines:150,
    keep_method_body_max_lines:8}} + Configuration accessors.
    
    Specs: skeleton correctness, pointer offset/limit returns the exact body,
    small/non-Ruby/parse-error/insufficient-saving no-ops, off-by-default read tool
    unchanged, telemetry numbers, drill-in logging. rubocop clean.

    feat(tools): add fuzzy-match fallback to edit and multi_edit
    
    When a byte-exact old_string match fails, the model has usually retyped
    the snippet with cosmetic drift: smart quotes for ASCII quotes, en/em
    dashes for hyphens, exotic spaces for plain spaces, dropped trailing
    whitespace, or a different Unicode form. Port pi's edit-diff concept: on
    an exact miss, normalize both the file content and old_string (NFKC,
    smart quotes -> ASCII, dashes -> '-', exotic spaces -> space, strip
    trailing whitespace per line) and locate the normalized needle in the
    normalized content.
    
    Normalization is used ONLY to locate the span: matches map back to the
    ORIGINAL byte range via a normalized-char -> original-byte offset map and
    the replacement splices into the untouched original bytes, so normalized
    text is never written to disk. Matches must align to original-character
    boundaries, so a length-changing normalization (e.g. NFKC ligature
    expansion) can never splice mid-character. Uniqueness is still enforced:
    an ambiguous fuzzy match returns the same duplicate-context error;
    replace_all applies to all fuzzy matches.
    
    The byte-exact path and all its outputs are unchanged - the fuzzy path
    is a pure fallback on miss. Normalization and splice live in one shared
    Rubino::Tools::FuzzyMatch module used by both tools.
    
    Adds specs for smart quotes, em dash, trailing whitespace, ambiguous
    fuzzy match, length-changing NFKC offset mapping, and confirms the exact
    path is untouched.
